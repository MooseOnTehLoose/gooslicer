# Stage 2: LAN printer control specification (SDCP)

Source: `EleNetManager.dll` from SatelLite 1.0.2.43 (SHA-256 `4ddaca89…8a0417`), analysed with Ghidra 12.2 through REA.
The evidence bundle is `evidence/elenetmanager-lan-sdcp.json` (45 records). Addresses are VAs with image base 0x180000000.

**Everything here is static analysis. No printer traffic has been captured yet.**
Tags: [OBSERVED] means seen in decompiled code or disassembly. [INFERRED] means deduced from it.
[PUBLIC-SPEC] means the value was not named in the binary, so the name comes from Elegoo/CBD's published SDCP v3 documentation.
[UNKNOWN] means not established.

---

## 1. Discovery (UDP)

### Probe
- **Payload:** the 6 ASCII bytes `M99999`, with no terminator. [OBSERVED `FUN_18006ee30`, `FUN_180076110`]
- **Destination port:** UDP **3000**. [OBSERVED: `writeDatagram(..., 3000)`]
- **Destinations.** Two senders exist:
  - `FUN_18006ee30` walks every network interface except types 1 and 2 (Qt's Loopback and Virtual [INFERRED from the Qt enum]). For each interface it sends to the broadcast address of the first IPv4 entry, then also sends once to a caller-supplied address. [OBSERVED]
  - `FUN_180076110`: for each configured IPv4 string, it finds the local interface entry with that IP and computes `broadcast = ip | ~netmask`. It then sends the probe there. [OBSERVED]

### Reply
The reply is handled in `FUN_1800730d0` (readyRead).
- **Self-echo:** any datagram equal to `M99999` is ignored (the app sees its own broadcast). [OBSERVED]
- **Format:** the datagram is parsed as a JSON object and is accepted only when it has the top-level key `Id`. [OBSERVED]
- **Fields read** [OBSERVED]:

| JSON path | Type read as |
|---|---|
| `Id` | string |
| `Data.Attributes.Name` | string |
| `Data.Attributes.MachineName` | string |
| `Data.Attributes.ProtocolVersion` | string |
| `Data.Attributes.FirmwareVersion` | string |
| `Data.Attributes.Resolution` | string of the form `"<w>x<h>"`, split on `x` into two ints |
| `Data.Attributes.MainboardIP` | string |
| `Data.Attributes.MainboardID` | string |
| `Data.Attributes.SDCPStatus` | int |
| `Data.Attributes.LocalSDCPAddress` | string |
| `Data.Attributes.SDCPAddress` | string |
| `Data.Status.CurrentStatus` / `PreviousStatus` | int |
| `Data.Status.PrintInfo.{Status, Filename, CurrentLayer, TotalLayer}` | int / string / int / int |
| `Data.Status.FileTransferInfo.{Status, DownloadOffset, CheckOffset, FileTotalSize, Filename}` | int ×4, string |

- **Variant replies:** [UNKNOWN] whether every firmware nests these under `Data.Attributes`. Public SDCP v3 docs show a flat `Data{…}`.
  - The clean-room parser accepts both. That is a design choice, not observed behaviour.

## 2. Transports to the printer
Two transports exist, chosen per printer.

### 2a. SDCP over WebSocket ("v3 style")
- **URL:** `ws://<MainboardIP>:3030/websocket`. [OBSERVED string `0x1803c9f90`, used at `0x180079c36`]
- **Framing:** each request is a text frame, sent only when `QWebSocket::state() == ConnectedState (3)`. [OBSERVED `FUN_18007af10`]
- **Keepalive:** no application-level keepalive was found in the SDCP code. The only `ping` string belongs to a statically linked third-party library (code at `0x1801c5bdb`). [OBSERVED, bounded search]
  - QWebSocket answers protocol-level ping frames itself.

#### Request envelope
Built by `FUN_18007af10`, which is called through the exported `ManageDevice::SendSDCPRequest(int cmd, QString mainboardId, QJsonObject args)`. [OBSERVED]

```json
{
  "Id": "<connection Id string>",
  "Data": {
    "Cmd": <int>,
    "Data": { …per-command fields, see §3… },
    "RequestID": "<random UUID, hex, dashes removed>",
    "MainboardID": "<MainboardID>",
    "TimeStamp": <int, Unix **seconds**>,
    "From": 0
  },
  "Topic": "sdcp/request/<MainboardID>"
}
```

- **`RequestID`:** generated by `QUuid::createUuid().toString(fmt)` with `-` removed. [OBSERVED]
  - The `fmt` value is [UNKNOWN]. The clean-room client emits 32 lowercase hex characters with no braces. [INFERRED]
- **`TimeStamp`:** from `QDateTime::currentSecsSinceEpoch()`. [OBSERVED]
- **`Id`:** the 5th argument of `FUN_18007af10`. Its source is [UNKNOWN]. The client sends the printer's discovery `Id`. [INFERRED]

#### Receive dispatch
Handled in `FUN_18007a030`. Each incoming text frame is parsed as JSON, then routed on its `Topic` prefix [OBSERVED]:

| Topic prefix | Handler |
|---|---|
| `sdcp/response/` | `FUN_180080010` (command acknowledgements) |
| `sdcp/status/` | `FUN_180080410` |
| `sdcp/attributes/` | `FUN_18007d4c0` |
| `sdcp/error/`, `sdcp/notice/` | compared, then **ignored** |

#### File upload (push)
Handled in `FUN_1800ca5e0`. [OBSERVED unless noted]
- **Request:** `POST http://<MainboardIP>:3030/uploadFile/upload` with `multipart/form-data`.
- **Chunking:**
  - Chunk size is **1 MiB** (`0x100000`); the last chunk is shorter.
  - Chunks are sent sequentially, one request per chunk. `Offset` is the byte offset of the chunk.
  - Each chunk is retried up to **3** times. Success means the `QNetworkReply` has no error; the response body is not read by this function.
  - Upload stops on a cancel flag (object+0x40).
- **Form parts, in this order** (`FUN_1800c9f50` adds the plain fields):
  1. `TotalSize`: decimal size of the whole file
  2. `Uuid`: a random UUID without dashes, the same for every chunk of one upload
  3. `Offset`: decimal byte offset
  4. `Check`: `"0"`
  5. `S-File-MD5`: MD5 of the **whole file** as lowercase hex (`QCryptographicHash(Md5=1)` then `toHex()`, in `FUN_1800ca080`)
  6. File part: header `Content-Disposition: form-data; name="File"; filename="<basename>"` and `Content-Type: application/octet-stream`. The body is the chunk bytes.
     - The disposition literal is matched to the string `form-data; name="File"; filename="`. [INFERRED]
- **After upload:** printing is started with Cmd 128 (`Filename`, `StartLayer`). The log tag `[PRINT][AUTO_START] route=lan_sdcp_transfer` confirms this flow. [OBSERVED string; INFERRED flow]

### 2b. SDCP over MQTT ("v1 style", e.g. Saturn 3 Ultra [INFERRED from model strings])

> **OUT OF SCOPE (decision 2026-11-23):** the Linux client does not implement this transport.
> Printers reporting `ProtocolVersion` below V3 are **no longer compatible**. In those cases:
> - `discover` prints a WARNING and marks them `"supported": false`
> - `cmd`, `upload`, `print` and `files` refuse to run (exit code 2) unless `--force` is given
>
> The findings below are kept for reference only.
- **Who connects to whom:** the PC runs a broker, `resources/mosquitto/mosquitto.exe -c mosquitto.conf`, listening on **4848** with anonymous access (`myconfig.conf`). [OBSERVED]
  - Discovery replies carry `LocalSDCPAddress` and `SDCPAddress`. [OBSERVED keys]
  - The printer, as the client, connects to the PC's broker. [INFERRED]
- **Publishing:** `FUN_180073f40` publishes only when the entity mode is `1`. It sends to `/sdcp/request/<MainboardID>` through `VoxMqtt::Publish`, and the topic has a **leading slash**. [OBSERVED]
- **Subscriptions:** `/sdcp/response/%1`, `/sdcp/status/%1` and `/sdcp/attributes/%1`. [OBSERVED strings]
- **Envelope:** same as §2a, with these differences [OBSERVED in `FUN_18006f3f0`, `FUN_18006f7c0`, `FUN_18006fc70`]:
  - there is **no `Topic` key**
  - `RequestID = QUuid::toString()` (Qt5 default, so `{xxxxxxxx-xxxx-…}` with braces and dashes [INFERRED from Qt5 API])
  - `TimeStamp` is in **milliseconds** (`currentMSecsSinceEpoch`)
  - JSON is serialized compact (`toJson(1)`)
- **Commands with fixed bodies:**
  - **Cmd 64:** `"Data": null` (a `QJsonValue(Type 0 = Null)` constructor, resolved from the IAT). Its meaning is [UNKNOWN].
  - **Cmd 128:** `{"Filename": <name>, "StartLayer": 0}`.
  - **Cmd 256 (pull transfer):** the printer downloads the file from the PC.
    - Fields: `{"check": <u8 flag>, "CleanCache": 1, "Compress": 0, "FileSize": <int64>, "Filename": <name>, "MD5": <hex>, "URL": "http://${ipaddr}:<port>/<path>.goo"}`.
    - `${ipaddr}` is sent **literally**. The printer is expected to substitute the PC address. [OBSERVED literal; INFERRED meaning]
    - So the PC must run an HTTP file server. [INFERRED] Its port is [UNKNOWN].

## 3. Command table
Values are [OBSERVED] immediates at callers of `SendSDCPRequest` (RVA 0xbe5c0). Payload fields are [OBSERVED] in `FUN_180079150`. Names are [PUBLIC-SPEC] unless marked.

| Cmd | Name | `Data` payload |
|---|---|---|
| 0 | status refresh | `{}` (not seen as an immediate) |
| 1 | attributes refresh | `{}` |
| 128 (0x80) | start print | `{"Filename": str, "StartLayer": int}` |
| 129 (0x81) | pause | `{}` |
| 130 (0x82) | stop | `{}` |
| 131 (0x83) | resume | `{}` |
| 192 (0xC0) | rename printer | `{"Name": str}` |
| 255 (0xFF) | cancel file transfer | `{"Uuid": str, "FileName": str}` |
| 258 (0x102) | file list | `{"Url": str}` (e.g. `/local`) |
| 259 (0x103) | batch delete | `{"FileList": [..], "FolderList": [..]}` (each defaults to `[]`) |
| 320 (0x140) | history task list | `{}` |
| 321 (0x141) | history task detail | `{"Id": [..]}` |
| 386 (0x182) | video stream on/off | `{"Enable": int}`; the app also keeps a per-device flag |
| 387 (0x183) | timelapse on/off | `{"Enable": int}` |
| 64 (0x40) | [UNKNOWN] (MQTT only) | `null` |
| 256 (0x100) | pull file transfer (MQTT only) | see §2b |

Any other Cmd value gets an empty `{}` as its `Data`. [OBSERVED: default return]

## 4. Windows to Linux mapping for this subsystem
| Windows/Qt mechanism | Linux clean-room choice |
|---|---|
| `QUdpSocket` broadcast | `socket(AF_INET, SOCK_DGRAM)` with `SO_BROADCAST`; interface netmasks from `ip -j addr` or the ioctl `SIOCGIFNETMASK` |
| `QWebSocket` | A minimal RFC 6455 client using only the standard library |
| `QNetworkAccessManager` multipart POST | `http.client` with a hand-built multipart body |
| `QCryptographicHash::Md5` | `hashlib.md5` |
| `tasklist`/`taskkill` + bundled `mosquitto.exe` | Not ported: MQTT transport is out of scope (see §2b) |

## 7. Client implementation (GooSlicer P3)
- **`elegoo_lan/client.py`**:
  - `PrinterSession` runs one WebSocket per printer on a reader thread.
  - It only starts reading a frame once `select()` reports data, so the periodic status refresh never splits a frame.
  - Responses are matched to requests by `RequestID` through futures. A non-zero `Ack` raises `SessionError` with the [PUBLIC-SPEC] meaning.
  - After a drop it reconnects with backoff (1 s doubling to 30 s).
  - It refuses pre-V3 printers.
  - `PrinterState` decodes `CurrentStatus` and `PrintInfo`. Unknown codes are shown as numbers, not guessed.
  - `check_file_for_printer` blocks uploads whose resolution or model does not match the printer, or that go to printers whose `SupportFileType` lacks GOO.
- **`elegoo_lan/upload.py`**:
  - A cancel flag is polled before each 1 MiB chunk.
  - On cancel, the session sends Cmd 255 with the transfer `Uuid` so the printer drops the partial file. [INFERRED from §3; not exercised on hardware]
- **`gooslicer_qt/printers.py`**:
  - Printer control, at the top of the Printer settings tab: find printers or add one by IP, with a red banner and connection refused for printers below V3.
  - Live state, layer, progress, remaining time and temperatures.
  - Pause/Resume and Stop; a file list with Print and Delete; "Send .goo…" with progress and Cancel.
  - The File menu has "Slice and send to printer" (Ctrl+Shift+R).
  - Upload, start, pause, stop and delete each ask for confirmation first; resume does not.
  - Known printers are kept in settings (`lan/printers`).
- **Tests:**
  - `tests/sim_printer.py` is a stateful simulator using the captured message shapes. It runs a printing/paused/stopped/complete state machine, reassembles uploads with an MD5 check, and also runs standalone (`python -m tests.sim_printer`).
  - `tests/test_client.py` covers the session.
  - `tests/test_gui_smoke.py::test_printer_control_against_simulator` drives the whole UI flow.
